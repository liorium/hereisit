# AdSense 수익화와 저관리 운영

## 고정 목표

유용한 무료 도구를 검색으로 발견하고 반복해서 사용하는 사이트를 만든다. 우선 수익 모델은
Google AdSense이며, 목표는 광고 수익에서 운영비를 뺀 수익과 적은 수동 관리다. 로그인 기반
유료 기능은 후속 선택지다. 광고 승인이나 매출, 완전 무관리를 보장하지 않는다.

## 2026-09-18 저장소 점검

- 기존 `PRODUCT.md`에는 유료 로그인 계획만 있었으며, 이번에 AdSense 우선 목표를 반영했다.
- 정적 도구 페이지, canonical URL, sitemap, robots, 관련 도구 탐색과 개인정보 페이지가 있다.
- 광고 스크립트, 게시자 ID, `ads.txt`, 광고 동의 설정은 현재 소스에서 확인되지 않는다.
  AdSense 계정의 신청·승인 상태는 저장소만으로 알 수 없다.
- 도구 화면은 작업 영역 중심이다. 이미지 압축·크기 조절부터 실제 옵션과 결과 해석을 설명하는
  정적 안내를 추가했다. 이 안내는 파일 선택과 실행 아래에 배치하며 새 클라이언트 의존성이 없다.
- 개인정보 안내는 현재 분석 통계를 설명한다. 실제 광고 연결 시 광고 제공자·쿠키·동의·설정
  방법을 실제 구성에 맞게 보완해야 한다. 광고가 이미 동작한다고 미리 표시하지 않는다.
- 2026-08-30 preflight run `33285619258`에는 `COST_ACCOUNTING_INCOMPLETE`,
  container provider `reachable:false`가 기록됐다. 과거 관측이며 현재 운영 상태로 단정하지 않는다.
  이는 단순 대기만으로 해소된다고 볼 수 없다. 비용 조회 실패의 원인과 지속 시간부터 확인한다.
- PDF 비용·복구 증거를 입력받는 브랜치 변경은 실제 비용 측정이나 복구 훈련의 완료를 뜻하지 않는다.

## 2026-09-18 공개 경로 재확인

- 홈페이지와 `/image/compress`는 HTTP 200으로 응답했다. 화면 응답만으로 파일 처리 성공을
  검증한 것은 아니다.
- `https://api.hereisit.app/health`는 HTTP 200, `status:ok`, `serverJobsEnabled:true`를
  반환했다. 이는 개별 작업의 서버 사용 허가를 증명하지 않는다.
- `Origin: https://hereisit.app`과 각각 새 익명 세션으로 `/v1/policy`를 조회한 결과,
  `image.optimize@1`, `pdf.optimize@1` 모두 HTTP 200,
  `execution:local`, `reason:SERVER_PROCESSING_DISABLED`였다. 파일은 업로드하지 않았다.
- 현재 차단의 내부 원인은 아직 확인하지 못했다. 읽기 전용 production preflight
  [35352668117](https://github.com/liorium/hereisit/actions/runs/35352668117)은 보호 환경 승인
  대기 상태다. 이 결과를 과거 비용 조회 실패와 동일한 원인으로 단정하지 않는다.
- 로컬 진단 스크립트는 HTTP 응답 전 실패도 고정된 분류로 표시하도록 보완했다.
  `contract-mismatch`는 배포 설정과 점검 코드의 사용량 계약 해시 불일치,
  `no-response`는 HTTP 상태를 얻지 못한 미분류 실패이며 네트워크 장애 확정을 뜻하지 않는다.
  원본 오류 내용은 출력하지 않는다. 이 수정은 아직 운영 점검에 반영되지 않았다.

## 다음 실행 순서

기반 이미지 갱신과 실제 이미지 재검증의 후속 결과는
[`2026-09-18-native-runtime-security-refresh.md`](2026-09-18-native-runtime-security-refresh.md)에
기록했다. 후속 패치 후 PDF 후보의 HIGH·CRITICAL 검출은 0건, 이미지 후보의 HIGH 검출은
8건이다. 직접 빌드한 라이브러리의 자동 검사 목록 누락도 있어 보안 작업은 완료되지 않았다.

2026-09-18 초기 회귀 점검에서 확인한 배포 제약(후속 결과는 아래 참조):

- `pnpm test`: 223개 파일, 3246개 테스트 중 3239개 통과, 7개 실패.
  시간 초과 3건이 포함된 세 파일은 다른 검사를 겹치지 않고 `--maxWorkers=1`로 재실행해
  71개 모두 통과했다. 전체 테스트가 통과했다고 해석하지 않는다.
- 나머지 4건은 `tests/image-engine-license-policy.test.ts` 단독 재실행에서도 실패했다.
  저장소의 취약점 예외 10건이 모두 2026-09-14에 만료됐고, 검증기가 이를 거부한다.
  예외를 실제 정책에서 읽는 테스트이므로 날짜나 테스트만 바꿔 통과시키지 않는다.
- `pnpm lint`는 테스트 종료 후 643개 파일에서 통과했고, `pnpm typecheck`는 12개 패키지에서
  통과했다. 첫 병렬 lint의 임시 테스트 파일 삭제 경고는 순차 재실행에서 발생하지 않았다.
- 기존 [보안 검토 #141](https://github.com/liorium/hereisit/issues/141)은 자동 연장을 금지하고
  수정 패키지 적용 또는 정확한 새 이미지 digest에 대한 재검토를 요구한다.
- Debian 공식 추적기에서 [GLib CVE-2026-58010](https://security-tracker.debian.org/tracker/CVE-2026-58010)은
  trixie `2.84.4-3~deb13u4`부터,
  [OpenSSL CVE-2026-14456](https://security-tracker.debian.org/tracker/CVE-2026-14456)은
  `3.5.7-1~deb13u2`부터 수정으로 표시된다. 나머지 GLib 항목은 각각 다시 확인해야 한다.
  [Expat CVE-2026-66046](https://security-tracker.debian.org/tracker/CVE-2026-66046)은 현재 trixie
  `2.8.3-1~deb13u1`에서도 vulnerable로 표시되어 단순 snapshot 갱신만으로 해결된다고 볼 수 없다.
- 다음 보안 작업은 고정된 Debian snapshot과 distroless 런타임 갱신 후보를 검증하고 새 이미지의
  실제 SBOM·취약점 결과를 확인하는 것이다. 수정된 패키지가 실제 산출물에 포함되는지 확인하기
  전에는 기존 예외를 지우거나 새 이미지가 안전하다고 판단하지 않는다.

후속 검증: Next.js, Sharp/libvips, Expat 패치를 적용하고 실제 후보 이미지의 소스·실행 파일·
취약점 결과를 확인했다. 해결된 옛 버전에 묶인 만료 예외 10건은 연장하지 않고 제거했다.
그 후 전체 단위 테스트 223개 파일, 3251개가 통과했다. 남은 util-linux HIGH 8건은 예외 처리하지
않았으며 배포 차단을 유지한다. 이 결과는 운영 배포나 실제 AdSense 연결 완료를 뜻하지 않는다.

1. 공개 도구의 정상 작업 완료와 서버 비용 집계 실패를 확인한다. 기존 예산 차단과 로컬 대체
   경로를 유지하고, 차단이 장기화되면 원인을 구분할 수 있는 제한된 진단과 알림을 제공한다.
2. 주요 도구의 지원 형식·제약·옵션 설명을 실제 구현과 맞춘다. 소개와 연락 안내는 실제 운영자
   정보와 사용할 수 있는 연락 채널이 확인되면 추가한다. 승인용으로 허위 정보를 만들지 않는다.
3. 실제 AdSense 게시자 ID와 사이트 상태를 확인하고 사이트 확인 방식, `ads.txt`, 동의 설정과
   개인정보 안내를 함께 적용한다. 계정 접근 없이 ID나 승인 상태를 추측하지 않는다.
4. 안내 콘텐츠 주변의 소수 광고 위치부터 시작한다. 선택·실행·다운로드와 광고를 명확히
   구분하고, 광고가 차단되거나 실패해도 작업이 완료되는지 hosted browser 테스트로 확인한다.
5. 검색 유입, 도구 성공·다운로드 요청, 광고 수익, 서버 비용과 수동 조치 횟수를 주 단위로
   검토한다. 기존 익명 집계를 우선 사용하며 파일 정보나 광고 클릭 추적을 자체 추가하지 않는다.

## 구현 판단 기준

- 광고를 늘리기 위한 강제 대기, 불필요한 페이지 이동, 자동 새로고침을 만들지 않는다.
- 다운로드 버튼과 혼동되는 광고를 배치하지 않는다. 광고 유무가 레이아웃을 크게 흔들지 않게 한다.
- 높은 서버 비용을 쓰는 기능은 수익·사용량 근거로 우선순위를 정한다. 기능 개수만으로 확대하지 않는다.
- 정상 상태는 요약하고 장애·비용·삭제 실패처럼 조치가 필요한 상황을 알린다.
- 승인 여부와 상관없이 유용한 도구와 자체 설명을 제공한다. 문서 분량이나 페이지 수를 승인 기준으로
  임의 설정하지 않는다. 대량 중복 콘텐츠와 근거 없는 경쟁사 성능 비교를 추가하지 않는다.

## 확인한 공식 기준

- [AdSense 사이트 준비](https://support.google.com/adsense/answer/7299563?hl=en):
  방문자에게 관련 있고 독자적인 콘텐츠와 쉬운 탐색을 제공한다.
- [광고 배치 정책](https://support.google.com/adsense/answer/1346295?hl=en):
  광고를 탐색·다운로드로 오인하게 만들거나 클릭을 유도하지 않는다. 자동 새로고침과 강제 광고
  시청 뒤 다운로드 제공도 피한다.
- [Google Publisher Policies](https://support.google.com/adsense/answer/10502938?hl=en):
  실제 광고 데이터 처리에 맞는 개인정보 고지와 관련 정책을 확인한다.
- [지역별 동의 관리 요구](https://support.google.com/adsense/answer/13554116?hl=en):
  EEA·영국·스위스 사용자에게 광고를 제공할 때 적용되는 Google 인증 CMP와 동의 요구를 확인한다.

광고 연결 단계에서 공식 정책과 계정 안내를 다시 확인한다. 위 실행 순서는 제품 판단이며
Google의 승인 보장이나 모든 사이트에 동일하게 적용되는 필수 페이지 목록이 아니다.
