# PDF compression workbench simplification design

**Date:** 2026-08-06
**Status:** Approved for implementation

## 목적

기존 스캔 PDF 압축 기능과 로컬 처리 경계는 유지하면서, 한 화면에 원본·설정·결과를 동시에 보여주는
3열 작업대를 단계별 단일 화면으로 바꾼다. 사용자는 현재 해야 할 행동 하나와 처리 결과만 바로 이해할
수 있어야 한다.

## 목표

- 파일 선택, 설정, 처리, 결과 중 현재 단계에 필요한 정보만 보여준다.
- 기본값은 기존과 같은 `균형 150DPI`이며 별도 설정 없이 바로 실행할 수 있다.
- 실행 전에는 전체 페이지가 이미지로 바뀐다는 필수 경고를 명확히 보여준다.
- 결과 화면은 `원본 용량 → 결과 용량`, 절약률, 다운로드 행동을 중심으로 구성한다.
- 모바일 320px, 키보드, 스크린 리더 사용성을 유지한다.
- 기존 로컬 Worker, 압축 계약, 분석 이벤트, 다운로드 방식을 그대로 재사용한다.

## 비목표

- 압축 코덱, DPI, JPEG 품질 또는 PDF 결과 변경
- 구조 보존형 PDF 압축 추가
- 서버 업로드 또는 새 처리 API 추가
- 자동 다운로드, 공유 버튼, 미리보기 또는 페이지 썸네일 추가
- 다른 PDF 작업대 동시 변경
- 새 의존성 또는 범용 UI 상태 관리 도입

## 검토한 접근

1. **기존 3열 화면을 CSS로 축소**: 변경은 작지만 원본·설정·결과가 계속 동시에 남아 사용 흐름이
   단순해지지 않는다.
2. **기존 컴포넌트 안에서 단계별로 하나의 화면만 렌더링**: 처리 로직과 상태를 재사용하면서 불필요한
   UI를 제거할 수 있다. 이 접근을 선택한다.
3. **새 작업대와 별도 상태 머신 작성**: 구조는 독립적이지만 검사, 취소, URL 정리, 분석 이벤트와 오류
   처리가 중복된다.

## 사용자 흐름

### 1. 파일 선택

다음 요소만 보여준다.

- `스캔 PDF 용량 줄이기`
- `PDF 선택` 기본 버튼과 드래그 앤 드롭 영역
- `PDF 1개 · 최대 50MB · 최대 100페이지`
- `파일은 이 기기에서만 처리돼요.`

파일을 선택하면 기존 `inspectPdfFile`로 페이지 수를 확인한다. 확인 중에는 `페이지 확인 중`과 `중단`
버튼만 보여준다.

### 2. 압축 설정

검사가 끝나면 다음만 보여준다.

- 파일명, 원본 용량, 페이지 수
- `균형`과 `최소 용량` 두 native radio 선택지
- 기본 선택인 `균형`에 `추천` 표시
- 모든 페이지가 이미지로 바뀌며 검색 가능한 텍스트와 문서 기능이 제거된다는 기존 경고
- `{페이지 수}페이지 용량 줄이기` 기본 버튼
- `PDF 교체` 보조 버튼

영문 장식 문구, 패널 번호, `LOCAL`, 선택 용량 합계, 별도 결과 자리표시자와 중복 상태 문구는 제거한다.

### 3. 처리

처리 중에는 다음만 보여준다.

- `PDF 용량 줄이는 중`
- 기존 Worker 이벤트에서 받은 단계 문구
- 실제 진행률과 완료 페이지 수
- `중단`

원본 정보, 압축 설정, 빈 결과 패널은 숨긴다. 가짜 진행률이나 예상 완료 시간은 만들지 않는다.

### 4. 결과

성공하면 다음 순서로 보여준다.

- `용량 줄이기 완료`
- `원본 용량 → 결과 용량`
- `{절약률}% 줄었어요`
- `PDF 다운로드 ↓` 기본 버튼
- 결과가 이미지 기반 PDF라는 짧은 안전 안내
- `다른 PDF 압축` 보조 버튼

처리 시간, 사용한 설정을 반복하는 상세 표, `같은 설정으로 다시 실행`, 공유 버튼은 제거한다. 다운로드는
사용자가 버튼을 누를 때만 기존 `downloadUrl`로 시작한다.

## 화면 상태와 데이터 흐름

화면은 기존 상태에서 파생한 다섯 단계 중 하나만 렌더링한다.

1. `select`: 아직 정상 검사된 파일이 없거나 선택·검사 오류가 발생함
2. `inspecting`: 선택한 PDF의 페이지 수를 확인 중
3. `setup`: 파일과 검사가 준비됨
4. `processing`: 압축 진행 중
5. `result`: 결과와 object URL 준비됨

별도 전역 상태나 새 상태 머신은 추가하지 않는다. 기존 `file`, `inspection`, `inspecting`, `processing`,
`progress`, `result`와 ref를 그대로 사용한다. 파일 교체, 설정 변경, 취소, 새 작업, unmount 때 기존
`invalidateActiveWork`와 `clearResult`가 Worker 및 object URL을 정리한다.

`runPdfCompressScannedJob`, `pdf.compress-scanned@1`, 결과 파일명, 1% 최소 절약 조건은 변경하지 않는다.
기존 제품 분석은 실행 수락, 성공·실패·취소, 다운로드 요청 시점에서 그대로 발생하며 파일 정보는 보내지
않는다.

## 오류와 복구

- 형식, 크기, 페이지 수, 손상·암호화 오류는 파일 선택 단계에서 짧게 표시하고 다시 선택할 수 있게 한다.
- 균형 설정이 1% 이상 줄이지 못하면 파일을 유지하고 `최소 용량` 시도를 안내한다.
- 최소 용량도 줄이지 못하면 원본 사용을 권장하며 가짜 결과나 다운로드를 만들지 않는다.
- 메모리 한도는 기존 설정별 안내를 유지한다.
- 처리 취소는 결과를 만들지 않고 같은 파일의 설정 단계로 돌아간다.
- 다운로드 활성화가 실패하면 결과와 다운로드 버튼을 유지해 다시 누를 수 있게 한다.
- 파일명, 파일 내용, object URL, 미리보기는 로그나 네트워크에 기록하지 않는다.

## 접근성과 반응형

- 각 단계 제목에 프로그램적으로 초점을 옮겨 현재 상태를 알린다.
- 진행과 오류는 하나의 `aria-live` 영역에서만 알리고 중복 발표하지 않는다.
- radio, 파일 선택, 진행률과 버튼은 native semantics를 유지한다.
- 모든 버튼은 최소 44px, 입력 글자는 최소 16px로 유지한다.
- 320px에서 한 열로 표시하고 가로 스크롤이 생기지 않게 한다.
- 절약 결과는 색상 없이도 원본·결과 레이블과 화살표로 이해할 수 있게 한다.

## 검증

기존 단위·브라우저 테스트를 유지하면서 E2E 기대 화면을 단계별 흐름에 맞춘다.

- 초기 화면에는 파일 선택 행동과 로컬 처리 안내만 표시
- 기본 균형 설정과 최소 용량 설정의 실제 압축 결과
- 처리 중 실제 페이지 진행과 즉시 취소
- 결과의 원본 용량, 결과 용량, 절약률 및 한 번의 명시적 다운로드
- 다운로드 실패 후 같은 결과에서 재시도
- 무감소·메모리·페이지 한도·지원하지 않는 브라우저 오류 복구
- 파일 교체, 새 작업, 취소, unmount의 Worker 및 object URL 정리
- 분석 실패가 처리·결과·다운로드를 막지 않음
- 파일과 파일명이 기기 밖으로 나가지 않음
- Chromium, Firefox, WebKit, 모바일 프로필과 320px 레이아웃

브라우저 PDF 결과는 바이트 동일성을 요구하지 않는다. PDF MIME 서명, 페이지 수와 방향, 이미지 해상도,
원본보다 최소 1% 작은 결과, 경고와 다운로드 동작을 검증한다.

## 완료 기준

- 각 단계에서 하나의 주 행동만 보인다.
- 결과 화면에서 용량 변화와 다운로드 행동을 즉시 이해할 수 있다.
- 압축 결과, 개인정보 경계, 취소와 정리 동작은 기존과 동일하다.
- 전체 `pnpm verify:all`이 통과한다.
