# 반응형 한글 타이포그래피 개선 설계

## 배경

HereIsIt의 홈과 모든 도구 화면은 기능과 가로 폭은 안정적이지만, 한글 제목과 설명이 음절 사이에서 자유롭게 줄바꿈된다. 그 결과 운영 화면에서 다음과 같은 고아 음절과 짧은 마지막 줄이 확인됐다.

- 320px 홈: `파일 작업, 여기서 / 끝.`, `필요한 도구를 바로 찾아 / 보세요.`
- 390px 홈: `찾아드려 / 요.`
- 1024px 홈: `파일 작업, 여기 / 서 끝.`
- 1280px과 1440px 홈: `찾아드려 / 요.`, `찾아보세 / 요.`
- 320px과 390px 설명: `시작하 / 거나`, `도구 / 를 찾으세요.`처럼 단어 또는 조사가 분리됨
- 768px 이상 카드: 짧은 카드 이름이나 설명의 종결어가 단독 줄로 남음

문제의 주원인은 홈과 도구 목록의 제목·설명에 한글 단어 단위 줄바꿈 규칙이 없고, 태블릿 카드에서 즐겨찾기 버튼이 별도 열을 차지해 문구 폭이 불필요하게 줄어드는 것이다.

## 목표

- 홈(`/`)과 모든 도구(`/tools`)의 한글 제목, 설명, 패널 문구, 카드 문구를 모바일부터 PC까지 자연스럽게 줄바꿈한다.
- 한글 단어 내부, 조사 직전, 한 음절과 문장부호만 남는 줄바꿈을 줄인다.
- 현재 문구의 의미, 브랜드 말투, 접근성 이름, 탐색 구조를 유지한다.
- 320px부터 1440px까지 가로 넘침 없이 기존 반응형 구조를 유지한다.
- 새 문구가 추가돼도 같은 규칙을 자동으로 적용받게 한다.

## 범위

### 포함

- 홈 히어로 제목과 설명
- 홈 파일 시작 영역의 제목과 설명
- 홈 분야별 도구 제목, 패널 제목과 설명
- 모든 도구 화면의 히어로 제목과 설명
- 모든 도구 화면의 필터 결과 제목과 설명
- 홈과 모든 도구 화면에서 사용하는 도구 카드의 이름과 설명
- 태블릿 폭에서 카드 문구 공간을 확보하기 위한 즐겨찾기 버튼 배치 조정
- 반응형 줄바꿈 회귀를 잡는 Playwright 검사

### 제외

- 이미지·PDF 작업대의 기능 문구와 처리 로직
- 도구 이름, 설명, 브랜드 문구의 전면적인 카피라이팅 변경
- 고정 `<br>`, 비분리 공백 문자, 화면 폭별로 복제한 문구
- 글꼴 추가 또는 새 런타임 의존성
- 경로, 검색 상태, 즐겨찾기 상태, 파일 처리 계약 변경

## 검토한 접근법

### 1. 언어 인식 CSS 규칙과 최소 레이아웃 보정 — 채택

제목에는 `word-break: keep-all`, `overflow-wrap: break-word`, `text-wrap: balance`를 적용한다. 설명에는 같은 안전 규칙과 `text-wrap: pretty`를 적용한다. 태블릿 카드는 즐겨찾기 버튼이 문구 열을 계속 차지하지 않도록 기존 소형 화면 배치를 확장한다.

장점은 문구 의미를 유지하고 이후 추가되는 문구에도 적용되며, 화면 폭마다 별도 줄바꿈을 관리할 필요가 없다는 점이다. `text-wrap`을 지원하지 않는 환경에서도 `keep-all`과 `break-word`가 안전한 기본 동작을 제공한다.

### 2. 고정 줄바꿈 또는 비분리 공백

특정 화면에서는 정확하지만 다른 폭과 글꼴에서 불필요한 줄바꿈이나 넘침을 만들 수 있어 채택하지 않는다.

### 3. 모든 문구를 짧게 다시 작성

현재 사례는 줄일 수 있지만 원인을 해결하지 못하고 브랜드 말투와 검색 문구를 불필요하게 바꾸므로 채택하지 않는다.

## 상세 설계

### 제목

홈과 모든 도구 화면의 `h1`, 주요 `h2`, 패널 제목에 다음 정책을 적용한다.

- 한글 단어 내부를 일반 줄바꿈 지점으로 사용하지 않는다.
- 여러 줄 제목은 가능한 한 비슷한 길이로 균형을 맞춘다.
- 화면보다 긴 예외 문자열은 컨테이너 밖으로 넘치지 않고 마지막 수단으로만 분리한다.
- 폰트 크기, 계층, 접근성 역할과 제목 문구는 유지한다.

`text-wrap: balance` 결과는 글꼴과 브라우저에 따라 조금 달라질 수 있으므로 정확한 줄 문자열을 계약으로 고정하지 않는다. 대신 의미 있는 단어가 중간에서 갈라지지 않고 한 음절 고아줄이 생기지 않는 것을 계약으로 삼는다.

### 설명과 카드 문구

리드 문단, 패널 설명, 카드 이름과 설명에는 한글 단어 보존과 자연스러운 마지막 줄을 우선하는 규칙을 적용한다.

- 설명은 `text-wrap: pretty`로 짧은 마지막 줄을 줄인다.
- 카드 이름은 `text-wrap: balance`로 두 줄 사이의 길이 차이를 줄인다.
- 기존 두 줄 말줄임과 카드 높이는 유지한다.
- 긴 영문 형식명, URL과 같은 공백 없는 문자열은 `overflow-wrap: break-word`로 넘침을 방지한다.

### 태블릿 카드 공간

현재 즐겨찾기 버튼의 소형 화면 배치는 600px 이하에서만 적용돼 768px 카드에서 문구 열이 지나치게 좁다. 이 배치를 800px 이하까지 확장해 버튼은 기존 44px 터치 영역을 유지하면서 카드 우측 상단에 배치하고, 카드 본문은 버튼과 겹치지 않는 우측 여백을 확보한다.

이 조정은 카드의 링크 영역, 즐겨찾기 접근성 이름, 키보드 순서, 저장 상태를 바꾸지 않는다.

## 오류와 호환성 처리

- `keep-all` 때문에 긴 단일 토큰이 생겨도 `overflow-wrap: break-word`가 가로 넘침을 막는다.
- `balance`와 `pretty`는 점진적 향상으로 사용하며, 미지원 브라우저에서도 읽기와 기능은 유지된다.
- 문구가 예상보다 길어져도 고정 높이나 `nowrap`을 사용하지 않아 세로 방향으로 확장할 수 있다.
- 카드의 기존 두 줄 말줄임은 유지하므로 목록 밀도는 변하지 않는다.

## 검증 설계

### 회귀 검사

Playwright에서 실제 브라우저 레이아웃을 검사한다.

- 대상 경로: `/`, `/tools`
- 모바일: 320, 360, 390, 430px
- 반응형 경계: 600/601, 800/801, 900/901, 1040/1041px
- PC: 1024, 1280, 1440px
- 로컬 엔진: Chromium, Firefox
- CI 추가 엔진: WebKit과 모바일 WebKit

검사는 다음을 확인한다.

- 대상 제목과 설명의 계산된 `word-break`가 `keep-all`이다.
- `Intl.Segmenter("ko")`와 `Range` 좌표로 본 시각적 줄에서 한글 단어가 중간 분리되지 않는다.
- 마지막 줄이 한글 한 음절과 문장부호만으로 구성되지 않는다.
- 카드 이름과 설명의 기존 줄 수 제한을 유지한다.
- 요소와 문서의 `scrollWidth`가 `clientWidth`를 넘지 않는다.
- 즐겨찾기 버튼이 카드 문구와 겹치지 않고 44px 타깃을 유지한다.

폰트 폴백과 브라우저 조판 차이 때문에 정확한 줄 수, 픽셀 스냅샷, 전체 줄 문자열은 단언하지 않는다. 줄의 Y 좌표를 묶을 때는 약 1px 허용치를 사용한다.

### 전체 검증

- `pnpm verify`
- 관련 Playwright 테스트를 Chromium과 Firefox에서 실행
- CI의 전체 브라우저 행렬 통과
- Cloudflare Pages 불변 미리보기에서 모바일과 PC 스모크 검사

## 완료 기준

- 운영에서 확인된 `끝.`, `요.`, `다.` 고아줄과 단어 중간 분리가 대상 화면과 대표 폭에서 재현되지 않는다.
- 홈과 모든 도구 화면의 제목·설명·카드가 320~1440px에서 가로로 넘치거나 겹치지 않는다.
- 기존 카드 말줄임, 즐겨찾기, 검색, 탭, 파일 시작 동작이 유지된다.
- 새 의존성, 파일 업로드, 처리 계약 변경이 없다.
- 전체 정적 검증과 다중 브라우저 회귀 검사가 통과한다.
