# PDF to image workbench simplification design

**Date:** 2026-08-07
**Status:** Approved for implementation

## 목적

기존 PDF 이미지 변환 기능과 로컬 처리 경계는 유지하면서, 파일·설정·빈 결과를 한꺼번에 보여주는
작업대를 단계별 단일 화면으로 바꾼다. 사용자는 PDF를 선택한 뒤 추천 설정으로 바로 변환하고 결과 파일을
다운로드할 수 있어야 한다.

## 목표

- 파일 선택, 설정, 처리, 결과 중 현재 단계에 필요한 UI만 보여준다.
- 기본값은 기존과 같은 `모든 페이지 · JPG · 150DPI · 품질 85`로 유지한다.
- 출력 형식은 바로 선택할 수 있게 하고 페이지 범위·해상도·JPG 품질은 한 설정 영역에 정리한다.
- 결과 화면은 변환한 페이지 수, 파일 수, 결과 용량과 다운로드 행동만 중심에 둔다.
- 한 페이지는 이미지로, 여러 페이지는 ZIP으로 내려받는 기존 동작을 유지한다.
- 모바일 320px, 키보드, 스크린 리더 사용성을 유지한다.
- 기존 검사 Worker, 변환 Worker, 계약, 분석 이벤트와 다운로드 방식을 재사용한다.

## 비목표

- PDF.js, 렌더링·인코딩 알고리즘, DPI, JPG 품질 범위 또는 결과 바이트 변경
- 페이지 썸네일, 시각적 페이지 선택기 또는 이미지 미리보기 추가
- 서버 업로드, 새 처리 API, 자동 다운로드 또는 공유 버튼 추가
- 여러 PDF 동시 변환, 부분 결과 또는 원본 내장 이미지 추출 추가
- 다른 이미지·PDF 작업대 동시 변경
- 새 의존성, 전역 상태 또는 범용 단계 컴포넌트 추가

## 검토한 접근

1. **기존 3열 화면을 CSS로만 축소**: 변경은 작지만 파일·설정·빈 결과가 계속 동시에 남아 흐름이
   단순해지지 않는다.
2. **기존 독립 작업대에서 단계별 화면만 렌더링**: 검사·처리·취소·정리 로직을 재사용하면서 불필요한
   UI를 제거할 수 있다. 이 접근을 선택한다.
3. **페이지 썸네일 선택기를 포함한 새 작업대 작성**: 페이지 선택은 쉬워지지만 변환에 필요하지 않은
   렌더링과 메모리 비용이 생기고 이번 UI 정리 범위를 넘는다.

## 사용자 흐름

### 1. 파일 선택

다음 요소만 보여준다.

- `PDF를 JPG·PNG로 변환`
- `PDF 선택` 기본 버튼과 드래그 앤 드롭 영역
- `PDF 1개 · 최대 50MB · 최대 100페이지 출력`
- `파일은 이 기기에서만 처리돼요.`

파일을 선택하면 기존 `inspectPdfFile`로 페이지 수와 페이지 크기를 확인한다. 확인 중에는
`페이지 확인 중`과 `중단` 버튼만 보여준다.

### 2. 변환 설정

검사가 끝나면 다음만 보여준다.

- 파일명, 원본 용량과 전체 페이지 수
- `JPG`와 `PNG` 출력 형식
- 기본 선택인 `JPG · 150DPI`에 `추천` 표시
- `모든 페이지` 기본 범위와 필요할 때 여는 `페이지·화질 설정`
- 설정 영역 안의 지정 페이지, 96·150·300DPI와 JPG 품질
- `{n}페이지 이미지로 변환` 기본 버튼
- `PDF 교체` 보조 버튼

설정 영역은 native `details`를 사용한다. 사용자가 지정 페이지, 기본값이 아닌 DPI 또는 JPG 품질을
선택하면 요약에 실제 설정을 표시하고 열린 상태를 유지한다. PNG에서는 JPG 품질을 숨긴다. 영문 장식
문구, 패널 번호, `LOCAL`, 파일 한도 반복, 별도 빈 결과 패널과 중복 상태 문구는 제거한다.

### 3. 처리

처리 중에는 다음만 보여준다.

- `이미지로 변환하는 중`
- 기존 Worker 이벤트에서 받은 단계 문구
- 실제 완료 페이지 수와 진행률
- `중단`

파일 정보와 설정은 숨긴다. 가짜 진행률, 예상 시간 또는 아직 만들지 않은 결과 카드는 표시하지 않는다.
취소하면 같은 파일의 설정 화면으로 돌아간다.

### 4. 결과

성공하면 다음 순서로 보여준다.

- `변환 완료`
- `PDF {원본 페이지 수}페이지 → {결과 파일 수}개 {JPG|PNG}`
- 결과 용량
- 한 페이지는 `{JPG|PNG} 다운로드 ↓`, 여러 페이지는 `ZIP 다운로드 ↓` 기본 버튼
- 텍스트 검색·선택이 불가능한 이미지가 된다는 짧은 안내
- `다른 PDF 변환` 보조 버튼

처리 시간, 설정 상세 반복, 세 가지 경고 목록, `같은 설정으로 다시 실행`, 공유 버튼과 자동 다운로드는
표시하지 않는다. 다운로드 실패 시 결과와 버튼을 유지해 다시 누를 수 있게 한다.

## 화면 상태와 데이터 흐름

화면은 기존 상태에서 파생한 다섯 단계 중 하나만 렌더링한다.

1. `select`: 정상 검사된 파일이 없음
2. `inspecting`: PDF 페이지 정보를 확인 중
3. `setup`: 파일과 검사가 준비됨
4. `processing`: 변환 Worker 실행 중
5. `result`: 결과와 다운로드 URL 준비됨

별도 상태 머신은 추가하지 않는다. 기존 `file`, `inspection`, `inspecting`, `processing`, `progress`,
`result`, `resultUrl`과 설정 상태를 그대로 사용한다. `runPdfToImagesJob`, `pdf.to-images@1`,
`planPdfToImagesRasterization`, 페이지 범위 파서, 파일명과 ZIP 규칙은 변경하지 않는다.

기본 실행은 기존 사양인 모든 페이지, JPG 품질 85, 150DPI를 그대로 Worker에 전달한다. 설정 변경은 기존
preflight를 다시 계산하고 이전 결과와 object URL을 정리한다. 파일 교체, 취소, 새 작업과 unmount 때
검사·변환 Worker를 종료하고 결과 URL을 해제한다.

기존 `PdfToImageWorkbench` 안에서 단계별 마크업으로 교체한다. 이 도구에만 필요한 단계 레이아웃은 전용
CSS module로 옮기고, 공용 `PdfWorkbench`나 다른 PDF 도구의 스타일·동작은 바꾸지 않는다.

## 오류와 복구

- 형식, 크기, 페이지 수, 손상·암호화 오류는 파일 선택 단계에서 짧게 표시하고 다시 선택할 수 있게 한다.
- 잘못된 페이지 범위, 출력 100페이지 초과와 픽셀·메모리 한도는 설정 옆에 정확한 수정 방법을 표시하고
  실행을 막는다.
- 지원하지 않는 브라우저는 파일을 읽기 전에 호환 브라우저 안내를 보여준다.
- 처리 취소는 결과를 만들지 않고 같은 설정 화면으로 돌아간다.
- Worker 실패는 파일과 설정을 유지해 다시 실행할 수 있게 한다.
- 다운로드 시작 실패는 결과와 다운로드 버튼을 유지한다.
- 파일명, 파일 내용, 결과 바이트와 object URL은 로그나 네트워크에 기록하지 않는다.

## 접근성과 반응형

- 단계가 바뀔 때 단계 제목에 프로그램적으로 초점을 옮긴다.
- 검사·처리 진행과 오류는 하나의 `aria-live` 영역에서만 알린다.
- 파일 선택, `details`, radio, range, 진행률과 버튼은 native semantics를 유지한다.
- 설정 요약은 형식, 범위와 DPI를 텍스트로 제공해 색상에 의존하지 않는다.
- 모든 버튼은 최소 44px, 입력 글자는 최소 16px로 유지한다.
- 320px에서는 한 열로 표시하고 버튼·페이지 범위 입력이 화면 밖으로 넘치지 않게 한다.
- 처리 취소 후 설정 제목으로, 결과 생성 후 결과 제목으로 초점을 옮긴다.

## 검증

기존 계약·계획·Worker 테스트를 유지하면서 브라우저 기대 화면을 단계별 흐름에 맞춘다.

- 초기 화면에는 파일 선택 행동과 로컬 처리 안내만 표시
- 기본 JPG 150DPI 실행과 PNG·지정 페이지·96·300DPI·JPG 품질 변경
- 잘못된 페이지 범위와 출력·픽셀·메모리 한도의 실행 차단 및 복구
- 처리 중 실제 페이지 진행과 즉시 취소 후 설정 복귀
- 한 페이지 직접 이미지 다운로드와 여러 페이지 ZIP 다운로드
- 결과의 원본 페이지 수, 파일 수, 형식, 용량과 한 번의 명시적 다운로드
- 다운로드 실패 후 같은 결과에서 재시도
- 파일 교체, 설정 변경, 취소, 새 작업과 unmount의 Worker 및 object URL 정리
- 분석 실패가 변환·결과·다운로드를 막지 않음
- 파일과 파일명이 기기 밖으로 나가지 않음
- Chromium, Firefox, WebKit, 모바일 프로필과 320px 레이아웃

브라우저 렌더링은 바이트 동일성을 요구하지 않는다. 이미지 MIME 서명, 출력 크기 허용 오차, 선택한
페이지 수와 순서, ZIP 항목 이름, 경고와 다운로드 동작을 검증한다.

## 완료 기준

- 각 단계에서 현재 필요한 주 행동 하나만 분명하게 보인다.
- 기본 설정 사용자는 PDF 선택 후 추가 조정 없이 바로 변환할 수 있다.
- 결과 화면에서 변환된 페이지·파일 수와 다운로드 형식을 즉시 이해할 수 있다.
- 변환 결과, 개인정보 경계, 자원 한도, 취소와 정리 동작은 기존과 동일하다.
- 전체 `pnpm verify:all`이 통과한다.
