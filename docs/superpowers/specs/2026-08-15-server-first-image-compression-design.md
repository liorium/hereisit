# 서버 기본 이미지 압축 설계

**Status:** Approved on 2026-08-15

## 결정

`/image/compress`의 기본 실행 경로를 기존 네이티브 이미지 서버 엔진으로 전환한다. 브라우저
로컬 처리는 사용자가 선택할 수 있는 개인정보 보호 옵션이자 서버 장애·비용 차단 시의 안전한
대체 경로로 유지한다.

새 엔진, API 또는 처리 계약은 만들지 않는다. 이미 구현된 `image.optimize@1` 서버 경로,
브라우저 Worker 경로, 정책 API, 결과 검증·삭제 수명주기와 비용 회로차단기를 재사용한다.
이 결정은 `/image/compress`에만 적용한다. 다른 도구의 로컬 우선 원칙은 그대로 유지하며, 파일이
기기를 떠나기 전에 UI가 이를 명확히 알려야 한다는 원칙도 변경하지 않는다.

## 사용자 경험

설정 화면은 한 가지 권장 경로를 먼저 보여준다.

- 기본 선택: `고성능 서버 압축`
- 안내: `선택한 파일을 HereIsIt 서버에서 처리하고 완료 후 삭제해요.`
- 선택 옵션: `내 기기에서 처리 · 파일 전송 없음`
- 실행 버튼: 기존 `용량 줄이기`

파일 선택만으로 업로드하거나 압축을 시작하지 않는다. 사용자가 파일을 확인하고 `용량 줄이기`를
누를 때 선택된 실행 경로가 시작된다. 서버 경로가 선택된 동안에는 실행 버튼 가까이에 위 안내를
한 줄로 계속 표시한다. 별도 동의 모달, 체크박스 또는 긴 보존 설명은 추가하지 않는다.

사용자가 로컬 처리를 선택하면 그 선택은 현재 브라우저에 저장해 다음 방문에도 유지한다. 서버를
다시 선택할 수 있으며 계정이나 로그인은 필요하지 않다.

## 실행 흐름

~~~text
파일 선택
  -> Worker에서 형식·크기·픽셀 검사
  -> 사용자가 용량 줄이기 실행
      -> 서버 선택 + 서버 정책 허용
          -> 기존 업로드/Queue/네이티브 엔진/검증/다운로드/삭제
      -> 로컬 선택
          -> 기존 브라우저 Worker 압축
      -> 서버 정책 거부 또는 안전한 서버 실패
          -> 같은 입력을 자동으로 로컬 Worker에서 처리
~~~

서버 압축 결과가 원본보다 작지 않으면 기존 규칙대로 원본을 유지하고 이를 압축 성공으로 과장하지
않는다. 서버 결과는 기존 검증과 다운로드 인계가 끝난 뒤 삭제하며 입력도 기존 수명주기와 sweeper를
통해 정리한다.

자동 로컬 전환은 업로드가 시작되지 않았거나 서버 소유 결과를 안전하게 정리할 수 있는 기존
재시도 가능 실패에만 적용한다. 전환할 때는 `서버를 사용할 수 없어 이 기기에서 처리했어요.`라고
결과를 숨김없이 알린다. 중복 업로드, 서버와 로컬의 동시 실행 또는 자동 서버 재시도는 하지 않는다.

## 정책과 비용

서버 기본 선택은 서버 사용을 강제하지 않는다. 정책 API가 다음 조건을 모두 통과할 때만 업로드를
허용한다.

- 이미지 서버 공개 입장 허용
- 비용·사용량 집계 정상
- 월 예상비용 상한 `5,000,000µUSD` 이하
- Queue, 삭제, 동시 작업과 할당량 경계 정상

하나라도 실패하면 정책은 로컬 실행을 반환한다. 비용 회로를 자동으로 강제 해제하거나 집계 오류를
무시하지 않는다.

이미지 서버 공개와 PDF 서버 공개는 별도 입장 상태로 유지한다. PDF 시각 검증 또는 외부 검토가
미완료여도 검증된 이미지 엔진의 배포·복구·공개를 막지 않아야 한다. 반대로 이미지 엔진 공개가 PDF
서버 공개를 암묵적으로 허용해서도 안 된다.

이번 변경은 Worker와 엔진 바이트를 바꾸지 않고 production Pages만 배포한다. 서버 공개는 이미 배포된
이미지 canary의 서명된 attestation·비용 회로·삭제 수명주기·브라우저 smoke를 다시 확인한 뒤 이미지
Queue만 재개하는 별도 운영 절차로 전환한다. 아직 배포되지 않은 PDF 리소스나 PDF 공개 상태는 만들거나
변경하지 않는다. 이후 Worker 또는 엔진 변경이 필요할 때는 해당 범위의 기존 전체 릴리스 게이트를
통과해야 한다.

## 개인정보와 관찰 가능성

- 서버 선택 상태에서만 파일 바이트가 기기를 떠난다.
- 파일 내용, 파일명, 썸네일, 원본·결과 바이트와 서명 URL을 로그·분석·배포 산출물에 기록하지 않는다.
- 분석에는 처리 위치, 형식, 제한된 크기 구간, 결과 상태와 절감률 구간 같은 비식별 값만 사용한다.
- 서버 안내는 화면과 접근성 트리에서 모두 읽을 수 있어야 한다.
- 로컬 선택은 실제로 네트워크 업로드를 만들지 않아야 한다.

## 검토한 접근

### 선택: 서버 기본 선택 + 명시적 로컬 옵션 + 자동 로컬 대체

네이티브 엔진의 압축 성능을 기본 제공하면서 개인정보 보호 선택과 가용성을 유지한다. 기존 두 실행
경로와 정책·수명주기를 그대로 사용하므로 가장 작은 변경으로 제품 목표를 달성한다.

### 제외: 서버 실패 시 오류로 중단

구현은 단순하지만 이미 동작하는 로컬 엔진을 버리고 사용자의 작업을 실패시킨다. 비용 상한에 닿을
때도 서비스를 사용할 수 없게 되므로 선택하지 않는다.

### 제외: 업로드 사실을 표시하지 않는 자동 서버 처리

처음 방문한 사용자가 파일이 기기를 떠나는 사실을 알 수 없고 프로젝트의 개인정보 원칙을 위반한다.
표시를 숨기는 대신 한 줄 안내로 최소화한다.

## 검증

- 서버가 기본 선택이고 안내가 실행 전에 보이는지 단위·렌더 테스트로 확인한다.
- 로컬 선택을 저장·복원하며 이 경로에서 작업 생성·파일 업로드 요청이 0회인지 확인한다. 파일을
  포함하지 않는 정책 조회는 화면 준비를 위해 허용한다.
- 서버 선택이 실제 `image.optimize@1` 계약과 네이티브 엔진 경로를 사용하는지 확인한다.
- 정책 거부, 비용 회로, 재시도 가능 서버 실패가 한 번만 로컬 처리로 전환되는지 확인한다.
- 취소, 파일 교체, 재실행, 페이지 이탈과 늦은 서버 이벤트가 중복 결과나 남은 원격 객체를 만들지
  않는지 확인한다.
- 서버 성공 결과의 검증·다운로드·삭제와 original-retained 동작을 확인한다.
- Chromium, Firefox, WebKit과 모바일 E2E는 GitHub Actions에서만 실행한다.
- 구현 완료 전 `pnpm verify`를 통과한다.

## 완료 조건

- 정상 정책에서 새 방문자의 기본 경로가 네이티브 이미지 서버 엔진이다.
- 실행 전 서버 처리와 완료 후 삭제가 한 줄로 명확히 표시된다.
- 사용자가 로컬 처리를 선택할 수 있고 파일 업로드가 발생하지 않는다.
- 서버가 불가능하면 작업이 자동으로 로컬에서 완료되며 전환 이유가 표시된다.
- 월 예상비용 상한 5달러와 기존 보안·삭제·로그 경계가 유지된다.
- 이미지 공개 상태가 PDF 공개 상태와 독립적으로 배포·복구된다.

## 제외 범위

- 새 코덱 또는 새 서버 처리 플랫폼
- 로그인, 결제, 유료 요금제와 사용자별 할당량
- PDF 서버 공개
- 압축 프리셋·파일 제한·결과 화면의 전면 재설계
- 로컬 Playwright 실행 또는 새 UI 의존성
