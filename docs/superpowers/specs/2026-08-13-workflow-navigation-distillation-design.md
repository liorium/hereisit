# 워크플로 탐색 단순화 설계

## 목표

현재 실행할 수 없는 `워크플로`가 홈의 주요 탐색을 차지하지 않게 한다. 사용자는 지금 완료할 수 있는 파일 선택, 도구 검색과 도구 목록에 집중한다. 향후 여러 기능과 실제 워크플로가 추가될 수 있는 코드·URL 경계는 유지한다.

## 선택한 접근

전역 탐색에서만 워크플로 진입점을 숨긴다.

- 데스크톱 주요 탐색의 `워크플로 · 준비 중` 링크를 제거한다.
- 도구 메가 메뉴의 워크플로 홍보 패널을 제거한다.
- 모바일 드로어의 워크플로 링크를 제거한다.
- `/workflows` 페이지, 메타데이터와 직접 URL은 삭제하거나 리디렉션하지 않는다.
- 완성된 워크플로가 생기기 전까지 푸터 링크나 별도 기능 플래그를 추가하지 않는다.

이 방식은 현재 사용할 수 없는 기능을 약속하지 않으면서도 향후 기능 확장을 막지 않는다. 실제 워크플로가 최소 하나라도 처음부터 끝까지 실행 가능해지면 그때 전역 링크를 다시 추가한다.

## 검토한 대안

1. **현재 노출 유지:** 미래 방향은 보이지만 사용자가 막힌 페이지에 도달하므로 제외한다.
2. **푸터에 낮은 우선순위 링크 유지:** 수요 확인 수단이 없고 현재 작업 완료에 도움이 없어 제외한다.
3. **페이지와 라우트까지 삭제:** 향후 확장 지점과 기존 직접 URL을 불필요하게 없애므로 제외한다.

## 구현 경계

변경은 공용 `SiteHeader`와 해당 스타일·브라우저 테스트에 한정한다. 도구 카탈로그, 파일 추천, 작업 실행 계약과 `/workflows` 페이지 내용은 변경하지 않는다. 제거된 홍보 패널 전용 CSS도 함께 삭제한다.

기존 클라이언트 탐색 수명주기 테스트에서 워크플로 링크를 이동 수단으로 사용한 경우에는 계속 노출되는 `내 도구` 경로로 바꾼다. 테스트의 파일 handoff·정리 검증 목적은 유지한다.

## 접근성·반응형

링크 제거 후 데스크톱과 모바일의 남은 탐색 순서가 자연스러워야 한다. 메가 메뉴의 키보드 진입, Escape 닫기, 포커스 복원과 모바일 드로어 포커스 트랩은 그대로 유지한다.

## 검증

- 브라우저 E2E 소스에서 데스크톱 주요 탐색, 메가 메뉴와 모바일 드로어에 워크플로 링크가 없음을 검증한다.
- `/workflows` 직접 방문과 비색인 상태 검증은 유지한다.
- 기존 클라이언트 탐색·포커스·파일 handoff 테스트를 유지한다.
- 로컬에서는 관련 비브라우저 검사와 `pnpm verify`를 실행한다. Playwright 브라우저는 저장소 정책에 따라 GitHub Actions에서만 실행한다.

## 완료 조건

- 사용자는 모든 주요 탐색 표면에서 현재 사용할 수 있는 목적지만 본다.
- `/workflows` 직접 URL은 계속 정상 렌더링된다.
- 기능 추가 구조나 처리 계약에는 변화가 없다.
- 관련 검사와 전체 저장소 검증이 통과한다.
