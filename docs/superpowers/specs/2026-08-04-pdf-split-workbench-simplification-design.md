# PDF 나누기 작업 화면 단순화 설계

## 배경

현재 PDF 나누기는 다음 두 작업을 이미 로컬 브라우저에서 지원한다.

- 모든 페이지를 각각의 PDF로 분리하고 ZIP으로 다운로드
- 입력한 페이지만 한 PDF로 추출해 다운로드

처리 성능과 계약은 충분하지만 화면은 합치기, 정리, 워터마크 등과 공유하는 3열 작업대다. 파일 한 개와 설정 하나만 필요한 작업에 비해 정보와 조작 요소가 많고, 처리 후에도 결과와 다운로드 행동이 바로 드러나지 않는다.

이번 변경은 처리 기능을 추가하지 않고 PDF 나누기의 선택, 실행, 결과 이해, 다운로드 흐름만 단순화한다.

## 목표

- 처음 방문한 사용자가 설명을 읽지 않아도 PDF 한 개를 선택하고 나눌 수 있게 한다.
- 기본 행동은 모든 페이지를 각각의 PDF로 분리하는 것으로 유지한다.
- 선택 페이지 추출은 같은 화면의 보조 선택지로 유지한다.
- 파일 선택 직후 전체 페이지 수를 확인하고 실행 전에 범위를 검증한다.
- 처리 결과를 페이지 수와 용량 변화로 명확하게 보여준 뒤 직접 다운로드한다.
- 모바일 320px 화면, 키보드, 스크린 리더 사용성을 유지한다.
- 기존 로컬 처리 계약과 브라우저 Worker를 재사용한다.

## 비목표

- 페이지 썸네일 선택기
- PDF 페이지 미리보기
- 새 서버 처리 경로 또는 업로드
- 새 PDF 기능이나 새 도구 경로
- `pdf.split@1` 계약 변경
- ZIP 구조와 결과 파일 이름 변경
- 다른 PDF 작업대의 동시 리팩터링

## 선택한 접근

기존 `PdfWorkbench` 안에 `split` 전용 단계 화면을 둔다. 공통 런타임, 상태 정리, pending-file handoff, 다운로드 유틸리티는 재사용하고 화면만 의도별로 분기한다.

기존 3열 화면을 CSS로 축소하는 방식은 구조적 복잡함이 남는다. 별도 컴포넌트로 완전히 분리하는 방식은 처리 상태와 오류 처리를 중복한다. 현재 범위에서는 기존 컴포넌트 안의 전용 단계가 가장 작고 유지하기 쉽다.

## 사용자 흐름

### 1. 파일 선택

첫 화면에는 다음 요소만 둔다.

- `PDF 선택` 기본 버튼
- 드래그 앤 드롭 영역
- PDF 한 개, 50MB 한도
- 파일이 기기를 떠나지 않는다는 짧은 안내

파일을 선택하면 `inspectPdfFile`로 페이지 수를 확인한다. 확인 중에는 `페이지 확인 중`과 중단 버튼을 보여준다. 확인에 실패하면 같은 화면에서 오류와 다시 선택할 수 있는 버튼을 제공한다.

### 2. 방식 선택과 실행

페이지 확인이 끝나면 다음만 보여준다.

- 파일명, 파일 용량, 전체 페이지 수
- `페이지별 분리`와 `페이지 추출` 선택
- 선택한 방식에 맞는 실행 버튼
- `PDF 교체`

`페이지별 분리`가 기본값이다. 설명은 `각 페이지를 PDF로 만들고 ZIP으로 저장` 한 줄로 제한한다. 실행 버튼은 `PDF 페이지별로 나누기`다.

`페이지 추출`을 선택하면 빈 페이지 범위 입력만 추가한다. placeholder는 `예: 1-3, 5`다. 입력은 기존 `parsePageSelection(value, maxPage)`로 문법, 중복, 실제 최대 페이지를 함께 검증한다. 유효한 경우 선택 페이지 수를 표시하고, 유효하지 않으면 짧은 오류를 표시하며 실행 버튼을 비활성화한다. 실행 버튼은 `선택 페이지 추출하기`다.

### 3. 처리

처리 화면에는 다음만 둔다.

- `PDF 나누는 중` 또는 `페이지 추출 중`
- 현재 단계
- 실제 진행률
- `중단`

진행률이 알려지지 않은 것처럼 보이는 가짜 애니메이션은 사용하지 않는다. 기존 Worker의 진행 이벤트를 그대로 표시한다.

### 4. 결과와 다운로드

페이지별 분리 결과는 다음을 표시한다.

- `나누기 완료`
- `12페이지 → PDF 12개`
- `원본 용량 → ZIP 용량`
- `ZIP 다운로드 ↓`
- `다른 PDF 나누기`

페이지 추출 결과는 다음을 표시한다.

- `추출 완료`
- `12페이지 → 3페이지`
- `원본 용량 → 결과 용량`
- `PDF 다운로드 ↓`
- `다른 PDF 나누기`

전자서명 무효화나 문서 기능 변경 경고가 있을 때만 다운로드 버튼 아래에 한 문장으로 표시한다. 자동 다운로드와 공유 버튼은 제공하지 않는다.

## 화면 상태

화면은 다음 다섯 상태 중 하나만 렌더링한다.

1. `select`: 파일 선택
2. `inspecting`: 페이지 수 확인
3. `setup`: 방식 선택과 실행
4. `processing`: 로컬 처리 진행
5. `result`: 결과 요약과 다운로드

한 상태의 보조 패널을 다른 상태에 남겨두지 않는다. 결과가 준비되면 설정과 파일 목록은 숨긴다. `다른 PDF 나누기`는 파일, 검사, 진행, 결과 URL을 모두 정리하고 `select`로 돌아간다.

## 내부 구조와 데이터 흐름

- `PdfWorkbench`의 기존 `items`, `processing`, `phase`, `progress`, `result`, `resultUrl` 상태를 재사용한다.
- merge에서 사용하는 순차 `inspectPdfFile` 흐름을 split의 단일 파일에도 사용한다.
- split의 실행 가능 조건은 검사 성공과 모드별 범위 유효성을 포함한다.
- 페이지별 분리는 기존 `{ operation: "split", selection: { mode: "every-page" } }` 명세를 사용한다.
- 페이지 추출은 기존 `{ operation: "split", selection: { mode: "extract", pages } }` 명세를 사용한다.
- `runPdfJob`과 브라우저 Worker가 기존과 같은 바이트, 진행 이벤트, 결과 메타데이터를 반환한다.
- 결과는 기존 object URL로 직접 다운로드한다. 새 작업, 파일 교체, unmount 때 URL을 폐기한다.
- 새 의존성, 네트워크 요청, 서버 API를 추가하지 않는다.

## 오류와 복구

- 지원하지 않는 형식, 빈 파일, 50MB 초과 파일은 선택 단계에서 거절하고 이유를 표시한다.
- 손상되거나 암호화되어 검사할 수 없는 PDF는 설정 화면으로 진행하지 않는다.
- 빈 범위, 잘못된 문법, 0 이하 페이지, 실제 페이지 수 초과 범위는 입력 아래에 표시한다.
- 처리 중단은 결과를 만들지 않고 같은 파일의 설정 화면으로 돌아가 재실행할 수 있게 한다.
- 메모리 및 출력 한도 오류는 파일을 유지한 채 다시 시도하거나 다른 파일을 선택할 수 있게 한다.
- 다운로드 활성화가 실패하면 결과와 다운로드 버튼을 유지하고 재시도를 안내한다.
- 파일명, 파일 내용, 썸네일, object URL을 로그로 남기지 않는다.

## 접근성과 모바일

- 파일 선택, 모드, 범위, 진행률, 결과 영역에 명확한 accessible name을 둔다.
- 모드는 native radio를 사용하고 선택 상태를 색상만으로 구분하지 않는다.
- 페이지 범위 입력은 모바일 확대를 막기 위해 최소 16px 글꼴을 유지한다.
- 버튼 높이는 최소 44px이며 320px에서 가로 스크롤이 생기지 않는다.
- 진행과 오류 메시지는 `aria-live`로 알리되 같은 내용을 중복 발표하지 않는다.
- 결과 제목, 요약, 경고, 다운로드 순서가 DOM 순서와 시각 순서에서 일치한다.
- 키보드 초점은 현재 단계의 첫 제목 또는 주 행동으로 자연스럽게 이동한다.

## 검증

기존 단위 테스트와 E2E를 유지하면서 다음 흐름을 명확히 검증한다.

- `parsePageSelection(value, maxPage)`의 기존 순수 단위 테스트로 문법과 최대 페이지 검증
- 유효한 PDF 선택 후 실제 페이지 수 표시
- 모든 페이지 분리 후 문서 수, 용량 비교, ZIP 직접 다운로드
- 한 페이지 PDF도 기존 계약대로 ZIP 다운로드
- 선택 페이지 추출 후 원본 페이지 수, 결과 페이지 수, PDF 직접 다운로드
- 범위 초과 시 인라인 오류와 비활성 실행 버튼
- 검사 실패, 처리 중단, 다운로드 실패 후 복구
- 처리 완료 전 자동 다운로드와 Web Share 미사용
- Chrome, Firefox, WebKit 및 모바일 프로젝트
- 320px 화면의 44px 터치 영역, 16px 입력 글꼴, 가로 오버플로 없음

브라우저 코덱 결과는 바이트 동일성을 요구하지 않는다. MIME 서명, 결과 페이지 수, 문서 수, 파일 이름, 경고, 허용 가능한 용량 관계를 검증한다.

## 완료 기준

- 사용자는 각 단계에서 하나의 주 행동만 본다.
- 페이지별 분리와 선택 페이지 추출이 기존 결과와 파일 이름을 유지한다.
- 페이지 수를 벗어난 범위는 처리 전에 막힌다.
- 결과 화면에서 무엇이 만들어졌는지와 어떤 파일을 다운로드할지 즉시 이해할 수 있다.
- 전체 `pnpm verify:all`이 통과한다.
