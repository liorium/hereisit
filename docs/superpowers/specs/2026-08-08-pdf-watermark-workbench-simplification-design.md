# PDF 워터마크 작업대 간소화와 처리 최적화 설계

**Date:** 2026-08-08
**Status:** Approved for implementation

## 목적

기존 PDF 워터마크 기능과 로컬 처리 경계를 유지하면서, 사용자가 문구와 적용 범위를 빠르게 정하고
결과를 바로 다운로드하는 단계별 화면으로 바꾼다. 처리 엔진은 원본 전체를 새 PDF로 복제하는 작업을
없애 대용량·다페이지 문서의 메모리 사용과 처리 시간을 줄인다.

## 목표

- 화면을 `PDF 선택 → 워터마크 설정 → 처리 → 다운로드` 네 단계로 단순화한다.
- 기본값 `대외비 · 가운데 · 48 · 18% · -45° · 전체 페이지`를 추천 경로로 유지한다.
- 문구, 배치, 적용 페이지만 먼저 보여주고 크기·색상·불투명도·각도는 native `details` 안에 둔다.
- 실제 파일 내용을 렌더링하지 않는 `모양 미리보기`로 현재 문구·배치·색상·불투명도·각도를 즉시 보여준다.
- 결과에는 적용 페이지 수, 원본·결과 용량, 다운로드와 다른 PDF 작업만 남긴다.
- PDF를 새 문서로 복제하지 않고 불러온 문서에 워터마크 이미지를 직접 추가한 뒤 저장한다.
- 새 의존성, 서버 업로드, 계약 변경 없이 기존 Worker와 PDF 라이브러리를 재사용한다.

## 비목표

- PDF 페이지 내용을 렌더링하는 썸네일 또는 시각적 페이지 선택기
- 이미지 워터마크, 사용자 글꼴, 자유 위치·각도 입력, 여러 워터마크
- PDF 압축, OCR, 서명 보존 보장 또는 서버 처리
- 다른 PDF 도구의 화면·계약·처리 경로 변경
- 시간 기반의 불안정한 성능 기준 또는 새 벤치마크 프레임워크

## 사용자 흐름

### 1. PDF 선택

- `워터마크를 넣을 PDF를 선택하세요`
- `PDF 선택` 버튼과 드래그 앤 드롭
- `PDF 1개 · 최대 50MB`
- `파일은 이 기기에서만 처리돼요.`

영문 장식 문구, 총 기기 한도 반복, 빈 결과 패널은 보이지 않는다.

### 2. 워터마크 설정

- 선택한 파일명과 용량, `PDF 교체`
- 필수 `워터마크 문구`
- `가운데 한 번 · 추천`과 `반복` 배치 선택
- `전체 페이지`와 `지정 페이지` 적용 범위
- 현재 모양을 보여주는 도식적 미리보기
- 접힌 `글자 모양 설정` 안의 크기, 색상, 불투명도, 각도
- `워터마크 넣기` 기본 버튼

지정 페이지의 기존 문법과 검증을 그대로 사용한다. 문구나 범위가 잘못되면 입력 가까이에 수정 방법을
보이고 실행을 막는다. 미리보기는 실제 PDF 내용이 아니라는 점을 `모양 미리보기`라는 이름으로 명확히 한다.

### 3. 처리

- `워터마크 넣는 중`
- Worker가 보고한 현재 단계와 실제 진행률
- `중단`

설정과 빈 결과는 숨긴다. 취소하면 파일과 설정을 유지한 채 설정 화면으로 돌아간다.

### 4. 결과

- `워터마크 완료`
- `전체 {n}페이지` 또는 `선택 {n}페이지에 적용`
- `{원본 용량} → {결과 용량}`
- `PDF 다운로드 ↓`
- 검색·선택할 수 없는 이미지 문구 및 기존 전자서명 무효화 안내
- `다른 PDF에 넣기`

처리 시간, 같은 설정 재실행, 공유, 설정 반복은 표시하지 않는다. 다운로드가 실패해도 결과와 버튼은
유지한다.

## 처리 엔진

현재 `watermarkPdf`는 원본을 읽은 뒤 새 `PDFDocument`를 만들고 모든 페이지를 `copyPages`로 복제한다.
워터마크는 한 번 렌더링·임베드되지만, 전체 문서 복제는 페이지 객체와 자원을 다시 만드는 불필요한
O(n) 작업이며 순간 메모리를 늘리고 문서 수준 메타데이터도 잃는다.

최적화 후에는 불러온 `source`를 출력 문서로 사용한다.

1. 기존 입력·페이지 범위·페이지 크기·회전 검증을 먼저 수행한다.
2. 워터마크 비트맵을 한 번 렌더링하고 `source.embedPng`으로 한 번 임베드한다.
3. `source.getPages()`의 선택된 페이지에만 기존 배치 계산 결과를 그린다.
4. 수정된 `source`를 기존 `savePdf`로 한 번 저장한다.

이 변경은 전체 페이지 복제와 `addPage`를 제거한다. 결과 페이지 수·순서·배치·파일명·경고·계약은 유지하며,
문서 제목 같은 원본 문서 수준 정보는 이전보다 더 잘 보존한다. 암호화·손상·출력 한도와 오류 처리는
기존 경계를 그대로 사용한다.

## 상태와 접근성

별도 상태 머신은 추가하지 않는다. 기존 `items`, `processing`, `progress`, `result`, `resultUrl`과 설정
상태로 화면 단계를 파생한다. 단계 제목은 `tabIndex=-1`과 ref로 전환 시 초점을 받는다. 진행과 오류는
하나의 `aria-live` 상태로 알리고, radio·range·color·details는 native semantics를 사용한다.

모든 조작은 최소 44px이며 입력 글자는 최소 16px이다. 320px에서는 설정과 미리보기가 한 열로 쌓이고
가로 스크롤이 생기지 않는다. 색상 없이도 선택 상태와 추천값을 텍스트로 이해할 수 있어야 한다.

## 검증

- 엔진 테스트는 실제 PDF에서 `copyPages`가 호출되지 않으면서 선택 페이지에만 워터마크가 추가됨을 확인한다.
- 원본 문서 제목과 페이지 수·순서가 결과에 유지됨을 확인한다.
- 기존 crop box, 회전, 페이지 범위, 비트맵 한도와 오류 테스트를 유지한다.
- 브라우저 테스트는 단계별 화면, 기본·반복 배치, 지정 페이지 검증, 처리·결과·직접 다운로드를 확인한다.
- 결과 교체·설정 변경·취소·새 작업·unmount의 object URL 정리를 유지한다.
- 외부 요청과 write 요청이 없고 파일명·내용·미리보기·object URL을 기록하지 않음을 확인한다.
- 데스크톱과 모바일 프로젝트, 320px 레이아웃에서 주요 버튼과 입력을 사용할 수 있어야 한다.

## 완료 기준

- 각 단계에서 현재 필요한 주 행동 하나만 분명하게 보인다.
- 기본 사용자는 PDF 선택 후 문구만 확인하고 바로 실행할 수 있다.
- 고급 모양과 지정 페이지는 필요할 때만 열어 조정할 수 있다.
- 워터마크 결과는 기존과 같고 전체 문서 복제는 발생하지 않는다.
- 기존 개인정보·메모리·오류·다운로드 경계가 유지된다.
- 관련 단위·브라우저 테스트와 전체 프로젝트 검증이 통과한다.
