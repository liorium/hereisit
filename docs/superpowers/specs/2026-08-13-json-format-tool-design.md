# JSON 정리·검사 도구 설계

**상태:** 2026-08-13 승인

## 목표

HereIsIt의 첫 비파일형 `quick` 도구로 JSON 문법을 검사하고, 원문의 값 표현을 바꾸지 않은 채
읽기 좋게 정리하거나 공백을 줄인다. 브라우저 안에서만 실행하고 새 의존성, 서버 처리, 계정,
저장 기능은 추가하지 않는다.

## 제품 범위

- 도구 ID: `data.json-format`
- 경로: `/data/json`
- 이름: `JSON 정리·검사`
- 도메인: `data`, `web-dev`
- 목적: `edit`, `convert`
- 경험: `quick`
- 실행: `browser`
- 계약: `json.format@1`
- 입력: 붙여넣은 JSON 텍스트, UTF-8 기준 최대 1 MiB
- 중첩: 최대 100단계
- 출력: UTF-8 기준 최대 4 MiB의 화면 텍스트와 명시적으로 내려받는 `application/json`

카탈로그, 검색, 즐겨찾기, 최근 도구, 관련 도구, 메타데이터, 사이트맵은 기존 경량 카탈로그에서
파생한다. 새로운 중앙 실행 레지스트리나 범용 quick 프레임워크는 만들지 않는다.

## 사용자 흐름

1. 사용자가 라벨이 있는 입력란에 JSON을 붙여넣는다.
2. `정리하기` 또는 `공백 줄이기`를 누른다. 입력 중 자동 실행하지 않는다.
3. 빈 입력, 1 MiB 초과, 잘못된 JSON은 입력 가까이에 한국어 오류로 표시한다.
4. 성공하면 원문 입력은 그대로 두고 별도 읽기 전용 결과 영역을 표시한다.
5. 사용자는 결과를 복사하거나 `formatted.json` 또는 `minified.json`으로 내려받는다.
6. `지우기`는 입력, 결과, 상태를 함께 초기화한다.

기본 동작은 `정리하기`이며 들여쓰기는 공백 두 칸이다. 결과는 자동으로 클립보드에 쓰거나
다운로드하지 않는다.

## 데이터 보존 경계

`JSON.parse()`와 `JSON.stringify()`로 결과를 재생성하지 않는다. 그 방식은 큰 정수, 소수 표기,
이스케이프 표기, 중복 객체 키를 바꿀 수 있다.

대신 다음 순서로 처리한다.

1. `TextEncoder`로 입력의 UTF-8 크기를 확인한다.
2. 네이티브 `JSON.parse()`는 문법 검증에만 사용하고 파싱 결과는 버린다.
3. 한 번의 문자열 순회로 문자열 내부와 외부를 구분한다.
4. 구조 문자를 순회하면서 중첩이 100단계를 넘으면 결과를 만들지 않는다.
5. 축소는 문자열 밖의 JSON 공백(`U+0020`, 탭, CR, LF)만 제거한다.
6. 정리는 문자열 밖의 `{`, `}`, `[`, `]`, `,`, `:` 주변 공백만 두 칸 들여쓰기로 다시 배치한다.
7. 결과가 UTF-8 4 MiB를 넘기 전에 중단한다.
8. 문자열, 숫자, 리터럴, 객체 키의 원문 조각은 그대로 복사한다.

따라서 `9007199254740993`, `1e+09`, `\u0061`, 중복 키처럼 재직렬화 시 달라질 수 있는 표현도
그대로 유지한다. 이 도구는 중복 키를 수정하거나 키를 정렬하지 않는다.

## UI와 접근성

기존 `ToolDetailPage`가 `quick` 경험을 `빠른 작업 영역`으로 렌더하도록 최소 확장한다. 파일 선택,
업로드 안내, 작업공간 UI는 넣지 않는다.

- 입력과 결과에는 항상 보이는 라벨을 둔다.
- 오류와 완료 상태는 `aria-live`로 알린다.
- 제출 오류가 발생하면 오류 요약으로 초점을 옮기고 입력과 연결한다.
- 버튼은 키보드로 모두 사용할 수 있고 작업 중 비활성화 상태를 만들지 않는다.
- 결과 영역은 긴 줄을 가로 스크롤하며 320px 화면에서 페이지 전체가 넘치지 않는다.
- 복사 실패는 결과를 유지한 채 명확한 재시도 안내를 표시한다.
- 다운로드용 객체 URL은 클릭 직후 해제하고 초기화·이탈 시 남기지 않는다.

## 오류와 개인정보

오류는 `EMPTY_INPUT`, `INPUT_TOO_LARGE`, `INVALID_JSON`, `NESTING_TOO_DEEP`,
`OUTPUT_TOO_LARGE`, `COPY_FAILED`의 내부 범주로 제한하고, 사용자에게는 짧은 한국어 메시지를
보여준다. 파서 예외 원문은 화면, 로그, 분석 이벤트로 내보내지 않는다. JSON 내용, 일부 내용, 키,
값, 결과, 클립보드 내용은 네트워크·로그·저장소로 보내지 않는다.

기존 방문 추적 외에 새 분석 이벤트는 추가하지 않는다. 입력은 React 상태와 현재 탭 메모리에만
존재하며 새로고침과 이탈로 사라진다.

## 코드 경계

- 순수 변환과 한도 상수는 웹의 작은 JSON 유틸리티 모듈이 소유한다.
- React workbench는 입력, 결과, 복사, 다운로드, 초점과 상태만 소유한다.
- 도구 페이지는 기존 패턴대로 카탈로그 ID와 workbench를 `ToolDetailPage`에 전달한다.
- 기존 discovery import 차단과 번들 예산을 유지한다.
- 다른 데이터 도구를 위한 추상화는 두 번째 실제 quick 도구가 같은 경계를 요구할 때만 검토한다.

## 검증

- 순수 단위 테스트: 빈/유효/무효 JSON, 중첩 구조, 빈 배열·객체, 문자열의 따옴표·역슬래시·구조
  문자, JSON 공백, 큰 정수, 지수·소수, 유니코드 이스케이프, 중복 키, 정확한 1 MiB 입력·100단계
  중첩·4 MiB 출력 경계.
- 카탈로그 테스트: ID·경로·계약·검색·관련 도구·구현 설정의 완전한 대응.
- 컴포넌트 경계 테스트: quick shell이 더는 거부되지 않고 `빠른 작업 영역`을 선택함.
- 호스팅 E2E 소스: 검색과 직접 경로, 정리·축소·오류·복사·다운로드·초기화, 외부 요청과 본문
  전송 없음, 키보드 초점, 320px 레이아웃.
- 전체 `pnpm verify`: 감사, lint, 타입, 단위·통합, fuzz, 빌드, 정적 내보내기, discovery import와
  번들 예산.

저장소 정책에 따라 Playwright 브라우저는 로컬에서 실행하지 않고 GitHub Actions에 맡긴다.

## 제외 범위

- JSON 파일 열기, 끌어놓기, 다중 파일 처리
- 트리 보기, 스키마 검사, JSONPath, diff, 키 정렬
- JSON5, 주석, trailing comma 자동 복구
- 자동 저장, 기록, 공유, 협업
- AI 설명, 로그인, 유료 기능
- 1 MiB 초과 입력과 Worker 기반 대용량 편집기

실제 사용 데이터가 1 MiB 제한이나 붙여넣기 흐름의 부족을 보여줄 때만 파일 입력 또는 Worker를
별도 버전 계약으로 설계한다.
