## Design Specificity Verdict

**LLM assessment:** HereIsIt 전용 기능과 신뢰 언어는 분명하지만 구성은 아직 범용 파일 유틸리티에 가깝다. 파일로 시작하는 추천, 로컬 처리 라벨과 종이·먹색 시각 체계는 제품 고유성이 있다. 반면 큰 히어로와 검색, 점선 드롭존, 범주 탭, 카드 그리드의 조합은 다른 도구 사이트도 그대로 사용할 수 있다. `친절한 편집 작업대`는 색상과 서체에는 보이지만 한 개의 작업 표면과 한 개의 추천 결과라는 공간 구조에는 아직 충분히 반영되지 않았다.

**Deterministic scan:** `apps/web/src/app/page.tsx`에 대한 Impeccable CLI 검사는 종료 코드 0, 정확한 결과 `[]`, 총 0건이었다. 래퍼 파일의 마크업 안티패턴은 없지만, 이는 하위 컴포넌트의 문구·상태·선택 구조에 대한 디자인 판단을 부정하지 않는다. 오탐은 없었다.

**Visual overlays:** 저장소 `AGENTS.md`가 일상적인 로컬 Playwright 실행을 금지하므로 브라우저 주입과 사용자 표시 오버레이는 실행하지 않았다. 신뢰 가능한 오버레이가 있다고 주장하지 않는다. 대체 증거는 독립 소스 검토와 성공한 결정론적 CLI 검사다.

## Overall Impression

첫인상은 차분하고 믿을 만하며 구현 완성도도 높다. 가장 큰 기회는 세 가지 동등한 시작점과 여러 동등 추천을 하나의 파일 중심 작업 흐름으로 정리하는 것이다. 사용자가 파일을 선택한 뒤에는 시스템이 비교 부담을 떠넘기지 말고 가장 잘 맞는 도구 하나를 이유와 함께 제시해야 한다.

## What's Working

1. **행동 옆에 신뢰 정보를 둔다.** 파일 확인 영역이 업로드하지 않고 앞부분만 확인한다고 바로 설명하고, 도구 카드는 실행 위치를 보여준다.
2. **접근성 구현이 의도적이다.** 검색 알림, 콤보박스 키보드 동작, 탭 로빙 포커스, Escape와 포커스 복원, 진행 상태 live region, reduced-motion 대응이 갖춰져 있다.
3. **시각 체계가 절제되고 일관된다.** 종이·먹색 표면, 촘촘한 한국어 제목, 평면 카드와 상호작용 시에만 나타나는 노란 그림자가 DESIGN.md 방향과 맞는다.

## Priority Issues

### [P1] 개인정보 보호 약속이 실제 서버 예외보다 절대적이다

- **What:** 홈의 `파일은 기기 밖으로 나가지 않아요`는 서버 처리 도구와 PRODUCT.md의 명시적 서버 선택 경계와 충돌한다.
- **Why it matters:** 개인정보 보호가 핵심 신뢰 약속이므로 나중에 서버 처리 라벨을 보면 동의 흐름이 안전하더라도 앞 문구가 기만적으로 느껴질 수 있다.
- **Fix:** `파일 확인과 대부분의 작업은 기기에서 처리하며, 서버가 필요한 경우 먼저 알리고 선택을 받는다`는 실제 불변식으로 고친다. 파일 런처 가까이에는 해당 동작에만 맞는 강한 로컬 문구를 유지한다.
- **Suggested command:** `$impeccable clarify`

### [P1] 맞는 도구 추천이 5–6개의 동등한 선택으로 끝난다

- **What:** 모든 결과가 같은 카드와 같은 `도구 선택` 버튼을 받으며 추천 순위와 이유가 보이지 않는다.
- **Why it matters:** 시스템이 줄여야 할 분류 부담을 사용자에게 다시 넘겨 `하나의 추천 경로` 원칙을 깨뜨린다.
- **Fix:** 첫 번째 준비 완료 결과를 `가장 잘 맞는 도구`로 올리고 한 줄 이유를 보여준다. 나머지는 `다른 작업 보기` 아래로 접고, 추가 파일 필요·개수 초과 도구는 별도 상태로 분리한다.
- **Suggested command:** `$impeccable distill`

### [P1] 오류 상태가 Honest State Rule을 위반한다

- **What:** 같은 오류가 녹색 `.status`와 빨간 `.correction`으로 중복 렌더링된다.
- **Why it matters:** 시각 신호가 충돌하고 보조기술 사용자에게 같은 오류가 반복 전달될 수 있다.
- **Fix:** live-region 메시지를 하나만 유지하고 상태에 따라 스타일과 역할을 매핑한다. 오류는 한 번만 alert로 표시하고 다음 행동을 함께 제공한다.
- **Suggested command:** `$impeccable harden`

### [P2] 사용할 수 없는 워크플로가 주요 탐색 공간을 차지한다

- **What:** `준비 중` 워크플로가 상단 링크, 메가 메뉴 강조와 모바일 목적지에 반복 노출된다.
- **Why it matters:** 사용자가 오늘 작업을 끝내는 데 도움 되지 않는 막힌 경로가 탐색 비용을 만든다.
- **Fix:** 실제 기능이 생길 때까지 주요 탐색에서 제거한다. 수요 확인이 필요하다면 푸터의 낮은 우선순위 안내 하나만 둔다.
- **Suggested command:** `$impeccable distill`

### [P2] 편집 작업대가 시각 스타일에만 머문다

- **What:** 화면 구조는 히어로/검색, 드롭존, 탭과 3열 카드의 통상적인 세로 나열이다.
- **Why it matters:** 카피와 기능은 HereIsIt 전용이지만 화면 구성은 다른 유틸리티 디렉터리와 교환 가능하다.
- **Fix:** 파일 객체와 작업 결과를 한 작업 표면의 중심으로 두고, 파일 입력에서 가장 적합한 다음 도구 하나로 자연스럽게 이어지게 한다. 기존 색상과 절제는 보존한다.
- **Suggested command:** `$impeccable layout`

## Persona Red Flags

**Jordan — 처음 방문한 사용자**

- 검색과 파일 선택 중 무엇이 추천 경로인지 바로 알기 어렵다.
- PDF 하나를 선택하면 합치기처럼 추가 파일이 필요한 항목까지 여러 동등 버튼으로 나타난다.
- `워크플로`가 무엇인지 모르지만 클릭할 수 있고 실제로는 준비 중이다.
- 절대적인 로컬 문구 뒤에 서버 처리 라벨을 보면 개인정보 보호 약속을 의심할 수 있다.

**Riley — 신뢰 경계를 확인하는 사용자**

- 홈의 절대적인 로컬 처리 문구와 서버 처리 도구의 모순을 즉시 찾는다.
- 오류가 녹색과 빨간색으로 동시에 나타나는 의미 불일치를 발견한다.
- 추천 결과가 정렬돼 있지만 UI가 기준을 밝히지 않아 추천의 근거를 검증할 수 없다.
- 준비되지 않은 기능이 여러 위치에 링크된 것을 제품 정직성 문제로 본다.

**Casey — 이동 중 사용하는 모바일 사용자**

- 파일 중심 경로가 히어로 검색 다음에 있어 작은 화면에서 스크롤해야 할 수 있다.
- 8개 범주가 가로 스크롤로 바뀌지만 더 있다는 시각 단서가 약하다.
- 모바일 메뉴의 기본 목적지와 추가 범주 선택이 겹쳐 방해 비용이 커진다.
- 반면 44px 메뉴 버튼, 전체 너비 파일 버튼과 1열 카드는 사용하기 좋다.

## Minor Observations

- 안전 그린 14px 상태 문구와 종이 배경의 대비는 약 4.36:1로 일반 텍스트 AA 기준에 약간 못 미친다.
- 데스크톱 헤더 동작은 최소 42px로 DESIGN.md의 44px 터치 목표보다 작다.
- 홈의 `SiteHeader`에는 `activePath`가 없어 현재 페이지 상태를 표시하지 못한다.
- 영문 눈썹 문구는 리듬을 만들지만 한국어 우선 제품에서는 범용 도구 사이트의 인상을 더한다.
- `H` 정사각형 로고는 깨끗하지만 파일과 작업대라는 제품 성격은 거의 전달하지 않는다.

5. 세 개의 탐색 위젯을 쌓는 대신 하나의 믿을 만한 작업대로 보이게 하려면 무엇을 중심에 둬야 하는가?
